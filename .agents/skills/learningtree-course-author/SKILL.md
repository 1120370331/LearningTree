将课程组织成学习者可以从节点进入内容页、在底部开始测验、依据结果继续解锁的科技树。先读取仓库根目录的 `docs/content-authoring.md`；处理内置前端课程时，以 `courses/builtin/frontend/catalog.json` 为编排来源。

## 编排规则

- 明确课程最终产出，然后按真实知识依赖拆分阶段。子树用 `parentTreeId` 分组，阶段前置用 `prerequisiteTreeIds`，树内依赖用节点 `parentId`。不要用长链强行串起互不依赖的知识。
- ID 是内容身份。改标题或补充讲义保留 ID；改变知识点含义时新增 ID。不要重用已删除 ID 表达另一主题。
- 总树只承载阶段导航时，不必添加占位测验。每个实际知识点必须有可直接阅读的讲义、回忆题与答案，以及适合目标的题目。
- 内容源码分别保存在 `lessons/<slug>.md` 与 `questions/<slug>.json`，catalog 只保存结构和路径。不要让生成后的课程包成为唯一维护源。
- 自动解锁沿用最近最多 5 次有成绩的自测，按题数加权，合计至少 5 题、正确率至少 80%。新题库的主观自评不计入成绩；旧版手工录入的自测记录继续兼容。若节点需要自动解锁，应提供足够的客观题。
- 保留现有树、稳定 ID 和引用关系。课程更新不夹带笔记、FSRS 卡片、答题历史或虚构完成状态。

## 交付

使用 `npm run courses:build` 组装内置课程包。普通外部课程遵循 `src/course-package.ts` 与 `docs/question-format.md`。写讲义时应用同目录的 `learningtree-lesson-author`；写题时应用 `learningtree-question-author`。

内置包首次自动装入数据库；已有安装标记时不自动覆盖用户编辑或恢复用户删除的课程。需要更新已经安装的内容时，明确告知使用课程包导入入口更新。

说明改动的阶段、知识点、来源文件和导入路径。执行范围遵循当前用户指示；用户要求交由其验收时，只完成制作和生成，不自行运行服务、测试或浏览器验收。
