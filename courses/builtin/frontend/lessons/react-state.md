# 状态、派生数据与副作用

## 学完要能做到什么

能用函数式更新处理连续状态变化，避免冗余状态，并为外部订阅写出对称清理。

## 核心概念

状态是某次渲染看到的快照。事件处理器读取当次渲染的值，多次 setCount(count + 1) 可能重复提交同一个新值。基于前一个状态计算时，使用 setCount(previous => previous + 1)。

能从 props 或现有状态直接计算的值通常不需要再保存为独立状态。过滤列表、完成数等可以在渲染时派生，避免两个来源不同步。需要优化时先确认性能成本，不要把所有计算都套进副作用。

Effect 用于与外部系统同步，例如订阅、定时器或网络连接。声明真实依赖并返回清理函数；重新运行之前会清理旧的 effect，卸载也会清理。开发环境 Strict Mode 的额外设置/清理有助于发现不对称资源管理。

## 读懂一个最小例子

```jsx
function Counter() {
  const [count, setCount] = useState(0);
  function addTwo() {
    setCount(n => n + 1);
    setCount(n => n + 1);
  }
  return <button onClick={addTwo}>{count}</button>;
}
```

两个更新函数依次基于前一次待处理值计算，因此一次点击增加 2。这里不需要 effect 来同步 count。

## 两个容易混淆的地方

- 当前渲染的状态是快照，更新会影响后续渲染。
- 匿名创建不同函数交给 removeEventListener 并不能移除原监听器。

- 任务更新使用明确的不可变数据流
- 监听设置与清理对称
