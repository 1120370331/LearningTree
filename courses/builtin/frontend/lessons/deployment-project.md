# 部署、恢复与毕业实战

## 学完要能做到什么

能交付一个可启动、可导入数据、可保存学习结果的完整作品，并说明环境配置、深链接和恢复策略。

## 核心概念

部署把构建产物、服务端程序、配置和持久化数据放到可运行环境。前端构建成功不代表后端数据库已就绪。应明确启动入口、健康状态、静态资源、API 地址和数据库路径，避免把可写数据放在会随发布替换的临时目录。

单页应用的深链接刷新通常需要静态服务器回退到入口文档，但 /api 路由必须保留真实 JSON 错误而非返回 HTML。公开部署还需要 HTTPS、认证、授权和相应运维边界；本地单用户应用不能自动等同于公开多用户服务。

发布要考虑失败与回滚。备份 SQLite 时应使用一致性备份方式，不能假定运行中的主文件单独复制就包含所有 WAL 数据。恢复需要兼容的代码、schema 和配置；仅保留旧前端文件不一定足够。

## 读懂一个最小例子

```text
# 示例部署配置，具体名称以项目约定为准
PORT=3001
DATABASE_PATH=/srv/learningtree/data/learningtree.sqlite
# 静态构建产物可替换；data 目录应持久化并独立备份。
```

将持久化数据与可替换产物分开。发布脚本、进程权限与目录挂载都必须遵守同一个路径约定，配置文件里不应写入公开仓库中的真实秘密。

## 两个容易混淆的地方

- 最新提交可能仍在 WAL；应使用支持一致性的备份方案或受控停机与检查点流程。
- 示例是路由伪代码；实际还要按框架处理路径安全与静态资源缺失。

## 动手完成一个小作品

毕业实战：完成一个可导入课程、浏览科技树、阅读课程、测验并保存历史的个人学习网页应用。

完成后，用下面的标准观察实际产出，而不是只看代码是否写完：

- 从课程导入到学习测验形成完整路径
- 客观判分与主观自评明确区分
- 学习历史存入数据库且内容与进度分离
- 启动、配置、数据备份和恢复说明齐全
- 真实限制被说明且无硬编码秘密

## 如何留下学习证据

先完成本节练习，再在底部开始测验。选择、填空、排序与代码阅读自动判分；简答、改错和实战需要你对照参考答案逐项自评。自评不会计入自动正确率，也不代表系统已经执行或审查你的代码。

把仍说不清的概念写进个人笔记。复习时先尝试回答“为什么“回滚前端文件”不一定能恢复一次有数据库变更的发布？”，再核对参考解释。
