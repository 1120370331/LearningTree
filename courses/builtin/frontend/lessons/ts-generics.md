# 泛型、约束与可复用接口

## 学完要能做到什么

能用泛型保留输入与输出之间的类型关系，并用 keyof 约束可访问属性。

## 核心概念

泛型不是给所有参数贴上任意类型，而是保留多个位置之间的关系。identity<T>(value:T):T 表示返回类型与输入类型一致；若改成 any，调用方会丢失原本有用的约束。

约束用于说明函数需要哪些能力。T extends {id:string} 允许保留更多字段，同时保证可以读取 id。K extends keyof T 表示键必须属于 T，返回 T[K] 才能继续精确描述属性值。

类型可推断时通常不必手写类型实参。不要为了抽象而增加无法表达关系的泛型，也不要用复杂条件类型掩盖简单业务模型。泛型同样属于静态层，不会自动验证 HTTP 数据或创建运行时值。

## 读懂一个最小例子

```typescript
function getProperty<T, K extends keyof T>(object: T, key: K): T[K] {
  return object[key];
}
const course = { title: "CSS", minutes: 20 };
const minutes = getProperty(course, "minutes");
```

minutes 保留 number 类型，错误键会受到静态约束。这里的泛型表达对象、键和值的关系，而不是放弃检查。

## 两个容易混淆的地方

- any 会放弃相关检查，调用方容易丢失类型信息。
- 返回类型应反映空数组可能性，而不只是换掉 any 的拼写。
