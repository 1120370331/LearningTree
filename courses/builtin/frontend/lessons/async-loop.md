# Promise、异步与事件循环

## 学完要能做到什么

能推演同步代码、微任务与定时器的顺序，并正确处理 async 函数的结果和失败。

## 核心概念

JavaScript 在当前任务内先运行同步代码。Promise 的 then 回调和 await 之后的继续执行通常进入微任务队列；当前栈清空后处理微任务，再开始后续任务。定时器的延时表示最早具备执行条件的时间，不保证准时执行。

async 函数始终返回 Promise。await 暂停的是该异步函数的后续逻辑，不会让整个浏览器停止响应。try/catch 可以捕获被 await 的拒绝，但未等待或未返回的 Promise 需要自己的处理路径。

独立请求可以用 Promise.all 并行等待，任意一个拒绝会使整体拒绝。业务允许部分成功时可考虑 allSettled。应根据失败语义和数据依赖选组合方式，不要为了并发忽略取消与过期结果。

## 读懂一个最小例子

```javascript
console.log("A");
setTimeout(() => console.log("D"), 0);
Promise.resolve().then(() => console.log("C"));
console.log("B");
```

在这里的浏览器脚本中，输出 A B C D。A/B 是同步工作；C 是微任务；零延时定时器仍需等当前任务及微任务处理后执行。

## 两个容易混淆的地方

- 当前同步栈会先完成；0 不是立即打断当前代码。
- 未 await 的异步拒绝不会被周围同步 try/catch 自动捕获；fetch 还需检查 HTTP 状态。
