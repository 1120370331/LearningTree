# Web 页面如何运行

## 学完要能做到什么

能说明 URL、请求、响应与浏览器渲染的关系，并在开发者工具中找到一次请求的状态和资源类型。

## 核心概念

浏览器不是把 HTML 当成图片下载。它通过 URL 定位资源，取得响应字节，再解析结构和样式。HTML 描述结构，CSS 参与布局与绘制，JavaScript 可以读取和改变页面状态。一个页面通常需要多个资源请求。

在一个没有缓存、没有已建立连接的简化流程里，浏览器先解析域名，再建立连接并发送 HTTP 请求；服务器返回状态、响应头和正文。实际浏览器会复用连接并并行加载资源，因此不要把教学顺序当成所有网络活动的唯一时间线。

状态码说明一次 HTTP 响应的结果，不等于整个产品业务一定成功。开发者工具的 Network 面板可以看 URL、状态、类型、耗时与响应正文；Elements 展示的是当前 DOM，可能已经被脚本修改。

## 读懂一个最小例子

```http
GET /guide.html HTTP/1.1
Host: learn.example

HTTP/1.1 200 OK
Content-Type: text/html

<h1>学习路线</h1>
```

请求行说明要取哪个资源，响应状态 200 表示这次请求成功。Content-Type 告诉浏览器正文的媒体类型；HTML 的标题随后才进入解析和渲染流程。

## 两个容易混淆的地方

- 脚本可以修改 DOM，因此当前 DOM 与初始 HTML 不一定相同。
- 资源类型和加载方式要匹配，不能只靠文件后缀期待浏览器自动纠正标签。

## 动手完成一个小作品

制作一个含标题、外部 CSS 和一张图片的小页面，记录三类资源在 Network 中的状态。

完成后，用下面的标准观察实际产出，而不是只看代码是否写完：

- 三类资源路径可对应到页面内容
- 记录至少一个成功与一个失败请求的现象
- 解释失败请求对页面造成的具体影响

## 如何留下学习证据

先完成本节练习，再在底部开始测验。选择、填空、排序与代码阅读自动判分；简答、改错和实战需要你对照参考答案逐项自评。自评不会计入自动正确率，也不代表系统已经执行或审查你的代码。

把仍说不清的概念写进个人笔记。复习时先尝试回答“为什么“页面白屏”不能只根据一个 200 状态码判断原因？”，再核对参考解释。
