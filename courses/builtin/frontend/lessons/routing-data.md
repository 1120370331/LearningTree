# 路由、表单与数据流

## 学完要能做到什么

能区分 URL 状态、临时界面状态与服务端数据，设计可刷新恢复的详情页与可靠提交反馈。

## 核心概念

路径参数适合定位资源，例如 /courses/42；查询参数适合表达可分享的筛选或分页。弹窗暂时展开状态未必需要写进 URL。选择状态归属时考虑是否需要刷新恢复、分享和前进后退。

服务端数据有加载、空、错误和过期状态，不能只用一个数组代表所有阶段。路由切换时旧请求可能晚到，需要取消或忽略过期响应；详情页也必须处理不存在的 ID。

表单应有明确的提交中、成功和失败反馈，失败保留输入，避免重复提交。客户端禁用按钮只能改善交互；涉及真正的重复写入风险时，还需要服务端幂等键或数据库约束。

## 读懂一个最小例子

```jsx
const params = new URLSearchParams(window.location.search);
const query = params.get("q") ?? "";
function searchUrl(nextQuery) {
  const next = new URLSearchParams(params);
  next.set("q", nextQuery);
  return `?${next.toString()}`;
}
```

URLSearchParams 负责参数编码并保留其他参数。真正应用还需要让路由系统订阅地址变化，避免只改地址栏却不更新界面。

## 两个容易混淆的地方

- 重试、多标签页和网络不确定性仍可能产生重复请求，需要服务端保证。
- 整条 URL 编码与单个参数编码不同，应使用针对查询参数的工具。

## 动手完成一个小作品

制作课程搜索页和详情页：搜索可分享，刷新详情可恢复，收藏表单失败后保留状态并可重试。

完成后，用下面的标准观察实际产出，而不是只看代码是否写完：

- 分享或刷新仍指向同一搜索或详情
- 旧请求不覆盖新路由数据
- 提交反馈明确且失败不丢失输入
