# 浏览器存储与安全边界

## 学完要能做到什么

能为偏好设置和结构化数据选择存储方式，识别 XSS、CSRF 与敏感凭证的边界。

## 核心概念

localStorage 是同源、同步、字符串键值存储，适合少量偏好；读写和 JSON 解析都可能失败。IndexedDB 更适合较多结构化数据及事务。浏览器存储可能被清理或受配额限制，不能把它当作永不丢失的唯一备份。

同源限制协议、主机和端口的组合。localStorage 中的数据可被同源脚本读取，不能因为“存在本机”就认为敏感信息安全。HttpOnly Cookie 限制脚本直接读取，但仍要正确配置 Secure、SameSite 与服务端权限。

XSS 让恶意脚本进入可信页面；减少危险 HTML 注入、正确编码与合理 CSP 都是防线。CSRF 则利用浏览器自动携带的凭证发起非预期请求，需要结合 SameSite、CSRF token 或来源检查等服务端策略，不能把二者混为同一问题。

## 读懂一个最小例子

```javascript
function readTheme(storage) {
  try {
    const value = storage.getItem("theme");
    return value === "dark" ? "dark" : "light";
  } catch {
    return "light";
  }
}
```

主题是低敏感的小字符串，读取失败可以安全回退。传入 storage 让依赖明确；持久化失败应有合理降级，而不是让整个页面无法加载。

## 两个容易混淆的地方

- HttpOnly 只是限制直接读取 Cookie，其他攻击面仍需防护。
- JSON.parse 成功也不保证数据结构正确，存储值同样需要验证。

## 如何留下学习证据

先完成本节练习，再在底部开始测验。选择、填空、排序与代码阅读自动判分；简答、改错和实战需要你对照参考答案逐项自评。自评不会计入自动正确率，也不代表系统已经执行或审查你的代码。

把仍说不清的概念写进个人笔记。复习时先尝试回答“为什么不应把 localStorage 当作敏感信息保险箱或唯一备份？”，再核对参考解释。
