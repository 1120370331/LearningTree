# 表单、约束与可访问名称

## 学完要能做到什么

能建立有标签、有正确提交数据、有可理解错误提示的表单，并区分客户端提示与服务端校验。

## 核心概念

label 为控件提供持续可见的名称。for 必须对应 input 的 id；name 决定普通表单提交时字段的键。placeholder 是提示，不应替代标签。

required、type=email、min 等原生约束可以帮助用户在提交前发现问题，但不能替代服务端校验。disabled 控件通常不会随普通表单提交，readonly 文本控件仍可提交。

错误需要说明哪个字段出了什么问题，以及如何修改。可将错误文本通过 aria-describedby 关联到控件，并用 aria-invalid 表明错误状态。不要只靠红色表达错误。

## 读懂一个最小例子

```html
<form>
  <label for="email">邮箱</label>
  <input id="email" name="email" type="email" required>
  <button type="submit">订阅</button>
</form>
```

id 用于标签关联，name 用于提交键名，两者职责不同。type=email 和 required 提供浏览器约束；后端仍需处理无效或恶意请求。

## 两个容易混淆的地方

- 请求可以绕过前端页面，后端必须校验自己的输入。
- 名称关联和提交键是两件不同的事，需要分别处理。

## 动手完成一个小作品

制作报名表，包含姓名、邮箱、可选备注和一个取消按钮；给无效邮箱提供文字反馈。

完成后，用下面的标准观察实际产出，而不是只看代码是否写完：

- 字段可见标签且提交键完整
- 错误提示可理解并关联到字段
- 取消不会误提交且错误后保留输入

## 如何留下学习证据

先完成本节练习，再在底部开始测验。选择、填空、排序与代码阅读自动判分；简答、改错和实战需要你对照参考答案逐项自评。自评不会计入自动正确率，也不代表系统已经执行或审查你的代码。

把仍说不清的概念写进个人笔记。复习时先尝试回答“为什么 placeholder 不能替代 label？”，再核对参考解释。
