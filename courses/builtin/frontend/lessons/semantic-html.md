# 语义化 HTML 与文档结构

## 学完要能做到什么

能用合适的标题、导航、主体和操作元素组织一张页面，并解释为什么语义不应由视觉样式替代。

## 核心概念

语义化是让标签表达内容角色。main 表示主要内容，nav 表示导航，article 适合可独立理解的内容。标签并不会自动保证内容质量，但能为浏览器、辅助技术和维护者提供稳定结构。

标题层级应反映内容关系，字号由 CSS 调整。为图标加上按钮语义，也必须提供可访问名称。跳转到地址通常使用链接，触发当前页面操作通常使用按钮。

原生控件带有键盘和交互语义。把 div 画得像按钮，并不会自动得到焦点、键盘激活或名称。优先选择原生元素，再按实际需要补充 ARIA，而不是覆盖原有语义。

## 读懂一个最小例子

```html
<main>
  <h1>学习计划</h1>
  <nav aria-label="章节"><a href="#html">HTML</a></nav>
  <section id="html"><h2>结构与语义</h2><p>先表达内容角色。</p></section>
  <button type="button">保存计划</button>
</main>
```

h1 描述页面主题，h2 是其子章节。链接跳转到章节，按钮执行保存操作。aria-label 为这组导航提供名称，没有改变它的导航角色。

## 两个容易混淆的地方

- 样式不能自动赋予按钮的焦点、键盘激活和语义。
- 修复应采用原生语义，而不是仅加 tabindex 后忽略其他行为。

## 动手完成一个小作品

把一篇文章改造成含导航、主体、章节标题和收藏操作的语义化页面。

完成后，用下面的标准观察实际产出，而不是只看代码是否写完：

- 标题层级与内容关系一致
- 链接和按钮按真实行为区分
- 操作可通过键盘访问且名称明确

## 如何留下学习证据

先完成本节练习，再在底部开始测验。选择、填空、排序与代码阅读自动判分；简答、改错和实战需要你对照参考答案逐项自评。自评不会计入自动正确率，也不代表系统已经执行或审查你的代码。

把仍说不清的概念写进个人笔记。复习时先尝试回答“如何判断一个界面动作应该用 a 还是 button？”，再核对参考解释。
